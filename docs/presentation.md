## 2. 演示脚本（照着念即可）

### 2.1 启动

```bash
conda activate base
cd /d/projects/vpteam/GLIDE-Net
python -m app.main --checkpoint ckpt/glide_net_6440647.pth \
    --detector runs/detect/detection/runs/neudet_yolov8m/weights/best.pt

```

### 2.2 单图检测（90 秒）

1. 打开「单图检测」Tab：“左边传图，右边出结果。上面这张是 RGB，下面可以传深度图。”
2. 拖入 `../datasets/NEU-RSDDS-AUG/Image_test/1.bmp` 与 `Depth_test/1.tiff`。
3. 点「开始检测」。
4. 指四联视图：“第一格原图，第二格深度，第三格是模型输出的概率热力图，第四格是最终
   掩膜叠在图上，框的颜色代表严重程度。”
5. 指报告卡：“这里给出判定——严重/中等/轻微，还有六项量化指标：面积占比、细长比、
   平均置信度、像素数、评分、类别。”
6. 指底部状态行：“端到端 175 毫秒左右：分割 118、检测 40。”

“把掩膜阈值从 0.5 拉到 0.7，看面积怎么缩、评分怎么降——所有数值都联动更新，
因为它们共用同一个 `InspectionReport`。”

   右边可以导出 CSV。”
4. 指“耗时”列第一行偏高：“第一张 800 多毫秒是 CUDA 冷启动，后面稳定在 175 左右。”

## 3. 预期提问与回答口径

**Q1：为什么不自己训练，而是用别人的 GLIDE-Net？**
“复现是课程要求的一部分。我们先把论文的四项指标逐项对齐到小数点后四位
（0.8718/0.9129/0.9475/0.0501），证明代码链路正确，再在其上做工程增量。
新增加的检测分支是从零训练的（YOLOv8m on NEU-DET）。”

**Q2：深度图看起来没用？**
“对，这是一个真实发现。数据集里的深度是 16 位 TIFF，`PIL.convert('L')` 会把它
饱和成纯白，所以消融里去掉深度那条 CNN 分支只掉 0.0042。我们量化了影响：
换成 min-max 拉伸后掩膜 IoU 仍为 0.9916，说明现权重对深度不敏感。
要让深度真正起作用，需要用拉伸后的深度**重训**——这是后续第一条工作。”

**Q3：分级有真值吗？怎么证明它准？**
“没有。数据集只有二值掩膜，没有严重程度标注，所以我们不把分级说成‘训练出来的模型’，
而是一条**可读的规则**：面积 × 细长 × 置信。我们做的是**标定**——统计 362 张真值的
面积分位数，把参考值定在 p93（0.55），使三档都有合理占比。报告里给了标定前后的对比，
也承认‘偏严重’这个口径选择（面向停机复检，宁可多报）。”

**Q4：175 ms 能上产线吗？**
“不能，这是笔记本 GPU 的数字（全量 362 张 P50 175 ms）。要上产线至少要做三件事：两路推理并行（预估 110 ms）、
TensorRT 或半结构化剪枝、以及把检测分支换成更轻的 n/s 模型。我们在报告里给了明确的
延迟预算拆分和优化项，但没有声称已完成。”

**Q5：为什么 ONNX 比 PyTorch 慢？导出不是应该更快吗？**
“导出≠加速。ONNX Runtime 的收益来自图优化和跨硬件，但 Hiera 里的 `Resize`/`Tile`
和大矩阵乘在 ORT CUDA EP 上没吃到 cuDNN 的 attention 内核，日志里能看到图被切段。
ONNX 在我们这里定位是**可移植**（fp32 ONNX 与 torch 的 MAE 只有 2.7e-05），不是加速。”

**Q6：100 张批量无崩溃怎么保证的？**
“`app/batch.py` 里每张图独立 try/except，失败写进 CSV 的 `error` 列并继续；
`--limit 100` 实跑结果 100 成功 0 失败，20.4 秒完成。这条记录在
`results/batch_100/batch.csv`。”

**Q7：7 个人真的都干活了吗？怎么分工的？**
“按模块边界分，每人一块可运行的代码或一组可复现的实验，分工表在 `docs/team.md`，
每一行都写了‘验收证据’——具体是哪个文件、哪条命令。比如 B 负责数据工程，
他交付的证据是 `docs/dataset.md` 里的统计表加上那条深度图测试。”

**Q8：有没有可能是数据泄漏？**
“测试集 362 张与训练集 1500 张是按文件名主名严格配对的独立目录，训练时只用
`Image_train`。我们没有在测试集上做任何拟合——包括分级阈值：那是用**真值掩膜的面积
分布**标定的，而面积分布本身不是评测指标，不会因此提高 S-measure 或 MAE。”

**Q9：这个系统的创新点到底是什么？**
“三处：一是把分割掩膜与检测框按 IoU 融合，让‘哪里’和‘什么’同时有答案；
二是把像素证据转成可读的三级判定，并做成单一事实来源的规则；
三是把整条链路工程化到可复现、可交接（脚本化图表 + 19 条问题记录 + 23 个单测）。
我们不声称算法创新超过原论文。”

**Q10：如果只有 RGB 没有深度怎么办？**
“可以直接跑。`app/engines/pipeline.py` 允许 `depth=None`，预处理会把深度通道置零，
模型支持 3 通道输入（`GLIDE_Net.forward` 里有显式分支）。代价是失去深度线索，
但系统不会崩——这一点在 UI 里深度图是可选上传。”

## 5. 三条明确的后续工作

1. **深度流重训**：用 min-max 拉伸的深度（而非饱和的 `convert("L")`）重训，
   验证 CMF/CNN 分支的真实贡献。需要 ≥16 GB 显存或分阶段冻结训练。
2. **两路并行推理**：分割与检测放两个 CUDA stream，目标把 175 ms 压到 ~110 ms；
   再评估 Torch-TensorRT 在独显机器上的收益（本机因内存不足未完成）。
3. **分级的有监督验证**：与产线合作获取“轻微/中等/严重”的人工评级，
   把当前规则作为弱标签基线，尝试学习式分级并做一致性检验（Cohen's κ）。
