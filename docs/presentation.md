# 课堂汇报与演示脚本

受众是老师和同学，多数人没做过显著目标检测。十二分钟要讲清三件事：我们做了什么、
这些数字凭什么可信、系统到底能不能跑起来。

幻灯片由 `node tools/make_slides.js` 从结果文件生成（14 页，16:9），不要直接改
`docs/slides.pptx`。数据变了重跑脚本，幻灯片跟着变。

```bash
cd tools && npm install   # 只需一次，装 pptxgenjs
node make_slides.js       # 重新生成 docs/slides.pptx
python ../tools/check_slides.py   # 回读检查溢出、重叠、越界
```

## 2. 讲台边界

一页讲不完的内容不要硬塞。下面这条线是给学生演示定的，不是给论文评审定的。

**要讲**

- 论文的四项指标复现结果，以及它为什么是后面所有工作的前提。
- 深度通道饱和这个发现。它推翻的是我们自己一开始的解释，讲出来比藏着有价值。
- 系统层面的实测数据：IoU、P50/P95 延迟、批量吞吐、0 失败。
- 没做成的部分，说清停在哪一步、卡在什么资源上、下一步怎么改。
- 现场能跑起来的那条命令。

**不讲或一句带过**

- TensorRT 的 DLL 排查细节。结论是"本机显存与页面文件不够"，过程留给文档。
- 40 项自检里每一条的名字。说"一条命令跑 40 项断言"就够。
- Git 提交怎么拆、文档怎么组织。被问到再答。
- 21 条问题清单的完整列表。挑三条有代表性的，其余指向 `docs/experiment-log.md`。
- 我们自己的测量方法与口径推敲（预热几次、同步在哪）。写进 `docs/deployment.md`，
  现场只说"两次独立重跑差不到 1%"。

判断标准很简单：这页内容能不能改变听众对你做的东西的判断。能，就讲；只是证明我们
很努力，就删。

## 3. 现场演示

### 3.1 启动

```bash
cd /d/projects/vpteam/GLIDE-Net
python -m app.main --port 7860 \
    --checkpoint ckpt/glide_net_6440647.pth \
    --detector runs/detect/detection/runs/neudet_yolov8m/weights/best.pt
# 浏览器打开 http://127.0.0.1:7860
```

启动约 4.5 秒。演示前先手动跑一遍，确认页面能出结果、端口没被占。

### 3.2 单图检测（90 秒）

1. 打开「单图检测」，上传 `../datasets/NEU-RSDDS-AUG/Image_test/1.bmp` 与
   `Depth_test/1.tiff`。
2. 指四联视图，说清每一格是什么：原图、深度、概率热图、掩膜叠加。
3. 指报告卡：判定档位、面积占比、细长比、置信度、评分、类别。
4. 指状态行：端到端 61 毫秒左右，其中分割 40、检测 11。

### 3.3 阈值交互（30 秒）

把阈值从 0.5 拉到 0.7，看面积和评分一起变。一句话解释：界面、CSV 和评测脚本
读的是同一份 `InspectionReport`，所以不会各说各话。

### 3.4 批量检测（60 秒）

切到「批量检测」，选 20 张，跑完指结果表：每张一行的判定、缺陷数、面积、档位、耗时。
第一张耗时偏高是 CUDA 冷启动，后面稳定在 76 毫秒左右。右边可以导出 CSV。

### 3.5 指标页（20 秒）

表格不是手抄的，直接从 `predictions/metrics.csv`、`ablation/metrics.csv`、
`docs/assets/latency.csv` 读出来渲染。改实验就同步变。

## 4. 提问准备

**为什么不自己训一个模型，而是复现别人的？**
复现是课程要求的一部分，也是我们后面所有增量的地基。四项指标对齐到小数点后四位，
说明代码链路和论文一致；检测分支则是我们从零训的，YOLOv8m 在 NEU-DET 上跑了 150 epoch。

**深度图是不是没用？**
用当前这份权重确实几乎没用。数据集里深度是 16 位 TIFF，`PIL.convert("L")` 会把它
压成纯白，深度通道成了常数，所以消融里去掉深度 CNN 只掉 0.0042。我们量化过影响：
换成 min-max 拉伸后掩膜 IoU 仍是 0.9916，说明现有权重没学到深度。要验证模块的真实
贡献得重训，这条列在后续工作第一条。

**分级没有真值，怎么证明它准？**
证明不了准确率，所以没把它说成训练出来的模型，而是一条读得懂的规则：面积、细长比、
置信度三项合成评分。我们做的是标定，统计 362 张真值的面积分位数，把参考值定在 p93
附近（0.55），让三档都有合理占比。口径是偏向停机复检的，宁可多报。

**61 毫秒能上产线吗？**
接近，但还不能这么说。这是笔记本 GPU 上的数字（362 张 P50 60.9 ms）。上产线至少还差
三件事：两路推理并行、TensorRT 或剪枝、更轻的检测模型。报告里给了延迟预算的拆分和
优化项，没有声称已完成。

**ONNX 为什么没比 PyTorch 快？**
导出不等于加速。收益来自图优化和跨硬件部署，而 Hiera 里的 Resize、Tile 和大矩阵乘
在 ORT 的 CUDA EP 上没吃到 cuDNN 的 attention 内核，日志里能看到图被切段。ONNX 在我们
这里的定位是可移植，不是更快。

**100 张批量怎么保证不崩？**
每张图独立 try/except，失败写进 CSV 的 error 列然后继续。`--limit 100` 实跑 100 成功
0 失败，8.87 秒完成，记录在 `results/batch_100/batch.csv`。

**七个人真的都干活了吗？**
按模块边界分，每人一块能跑起来的代码或一组能复现的实验。分工表和每行的验收证据
（哪个文件、哪条命令）都在 `docs/team.md`。

**有没有数据泄漏？**
测试 362 张和训练 1500 张是两个独立目录，文件名严格配对，训练只读 `Image_train`。
测试集上没有做过任何拟合，包括分级阈值——那是用真值掩膜的面积分布标定的，面积本身
不是评测指标，不会让 S-measure 或 MAE 变好看。

**创新点在哪？**
三处工程增量：掩膜与检测框按 IoU 融合，让"哪里"和"什么"同时有答案；把像素证据变成
可直接用于决策的三级判定，且只有一处定义；把整条链路做到可复现、可交接。算法本身
我们没有声称超过原论文。

**只有 RGB 没有深度怎么办？**
能跑。`app/engines/pipeline.py` 允许 `depth=None`，预处理会把深度通道置零，模型有
显式的 3 通道分支。代价是丢掉深度线索，界面里深度图本来就是可选的。

## 6. 三条后续工作

1. 用 min-max 拉伸后的深度重训，验证 CMF 与 CNN 分支的真实贡献。需要 ≥16 GB 显存，
   或者分阶段冻结训练。
2. 分割与检测放两个 CUDA stream，把 60.9 ms 压到 45 ms 左右；再评估 Torch-TensorRT
   在独显机器上的收益（本机因内存不足没做成）。
3. 与产线合作拿到人工评级，把当前规则当弱标签基线，做分级一致性检验（Cohen's κ）。
